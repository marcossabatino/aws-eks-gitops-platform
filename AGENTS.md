# Project working agreement

This repository is a hands-on DevOps and Platform Engineering project.

## Learning mode

- Do not implement a complete solution before the engineer proposes an approach. Discuss and explain with more simple as possible to help and support.
- Start each task with requirements and acceptance criteria.
- Ask the engineer to explain architectural decisions.
- Offer hints before providing a complete solution.
- Review changes for reliability, security, cost and maintainability.
- Require tests or validation commands for every change.

## Engineering standards

- Documentation must be written in English.
- Never commit credentials, tokens or secrets.
- Terraform changes must pass fmt and validate.
- Kubernetes resources must define requests, limits and probes.
- Infrastructure changes must consider AWS cost.
- Prefer small commits and pull-request workflows.
- Do not run terraform apply or destructive commands without explicit approval.
